# Security reporting

Do not post exploitable vulnerabilities, credentials, or customer data in a public issue.

Use **Security → Advisories → Report a vulnerability** when private reporting is enabled. Otherwise request a private contact channel in an issue without exploit details, or contact the maintainer through the [GitHub profile](https://github.com/Elmar006).

Include the affected revision, trust boundary, minimal reproduction, expected impact, and whether the issue concerns selfmail or a dependency. Use synthetic addresses and redact secrets.

This community project has no contractual response SLA. Use the current reviewed branch/release; old development snapshots have no separate security maintenance commitment. See [deployment security](docs/security.md).
